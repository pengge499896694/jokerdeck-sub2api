01

创建 SSH 密钥

在你的 Mac 本机执行，私钥只保存在本机。

检查是否已有密钥

ls -la ~/.ssh

如果已经有 id_ed25519 和 id_ed25519.pub，可以直接复用。

没有密钥时创建一对

ssh-keygen -t ed25519 -C "jokerdeck-deploy"

一路回车即可。私钥是 ~/.ssh/id_ed25519，公钥是 ~/.ssh/id_ed25519.pub。

首次把公钥放到服务器

ssh-copy-id root@123.56.108.167

这里只需要输入一次服务器密码。之后使用密钥登录，不要把密码发给任何人。

注意：不要复制或上传 id_ed25519 私钥。只需要传输以 .pub 结尾的公钥。
02

配置专用部署用户

登录服务器后执行，建议不要长期使用 root 发版。

# 阿里云/CentOS/Rocky/AlmaLinux 通常使用 wheel 组
usermod -aG docker deploy
usermod -aG wheel deploy

# 如果系统没有 sudo 命令，再安装它
dnf install -y sudo 2>/dev/null || yum install -y sudo

你的服务器提示「group 'sudo' does not exist」，说明它使用的是 RHEL 系列权限约定。Ubuntu/Debian 使用 sudo 组；阿里云/CentOS 系统使用 wheel 组。修改组后重新登录，组权限才会生效。

ssh-copy-id deploy@123.56.108.167
ssh deploy@123.56.108.167
03

设置 SSH 连接别名

之后不需要反复输入 IP、用户名和密钥路径。

mkdir -p ~/.ssh
chmod 700 ~/.ssh
cat >> ~/.ssh/config <<'EOF'
Host jokerdeck-prod
  HostName 123.56.108.167
  User deploy
  IdentityFile ~/.ssh/id_ed25519
  ServerAliveInterval 30
  ServerAliveCountMax 3
EOF
chmod 600 ~/.ssh/config
ssh jokerdeck-prod

我后续连接服务器时使用的就是这个别名。每次命令都会重新建立 SSH 连接，电脑重启后也可以继续使用。

04

Docker 发版流程

项目代码已经在服务器上的情况下，可以按这个顺序操作。

# 登录服务器
ssh jokerdeck-prod

# 进入项目目录
cd /opt/jokerdeck-sub2api

# 拉取最新代码
git pull --ff-only

# 更新并后台启动服务
docker compose -f deploy/docker-compose.yml up -d

# 查看容器状态
docker compose -f deploy/docker-compose.yml ps

# 查看应用日志
docker compose -f deploy/docker-compose.yml logs -f sub2api
推荐检查：发版后先访问 http://服务器地址/health，确认返回健康状态，再打开网页和客户端。
05

安全检查

配置完成后确认以下项目。

SSH 密钥登录能使用 ssh jokerdeck-prod 登录。
禁止暴露私钥私钥权限为 600，且没有上传到 Git。
防火墙只开放必要的 SSH、HTTP、HTTPS 端口。
数据持久化数据库和 Redis 使用持久化目录或 Docker volume。
备份发版前保留数据库和 deploy/.env 备份。
权限部署用户只执行必要的维护操作。
不要做：不要把服务器密码、SSH 私钥、JWT_SECRET、数据库密码或 API Key 粘贴到聊天、工单和截图中。
